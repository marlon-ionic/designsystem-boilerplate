# Angular Component Library

To create our Angular Component Library, we'll use [ng-packagr](https://github.com/ng-packagr/ng-packagr). This is a tool that allows us to create and Angular library in the [Angular Package Format (APF)](https://angular.dev/tools/libraries/angular-package-format). We'll use this tool to create a library that wraps our Stencil components.

To do this, we use the components generated from the [Stencil Angular Output Target](https://www.npmjs.com/package/@stencil/angular-output-target). The configuration we follow here is a specific implementation of the [more general documentation](https://stenciljs.com/docs/angular) found on the Stencil site.

## Create the Project

The first thing we need to do is generate the project's folders and the `package.json`.

```bash
cd packages
mkdir angular
cd angular
pnpm init
```

## Modify the `package.json` File

The `package.json` file generated by `pnpm init` is not appropriate for an Angular library. We need to make the following changes:

- Update the `name` to `@placid/angular`
- Remove `private: true` to allow the package to be published.
- Add the `description`, `license`, `homepage`, `repository`, `files`, `keywords`, `peerDependencies`, and `publishConfig` values (see bellow for a sample).
- Add the following dependencies:
  
  ```bash
  pnpm add @placid/core --workspace
  pnpm add ng-packagr typescript@~5.5.0 tslib@^2.3.0 -D
  pnpm add @angular/common@>=14.3.0 @angular/core@>=14.3.0 rxjs@>=7.5.0 --save-peer
  ```

When you are finished, your `package.json` file should look something like this:

```json
{
  "name": "@placid/angular",
  "version": "0.0.1",
  "description": "Angular Component Library for @placid/core web components",
  "author": "Outsystems",
  "homepage": "https://github.com/stencil-community/designsystem-boilerplate",
  "license": "MIT",
  "repository": {
    "type": "git",
    "url": "git+https://github.com/stencil-community/designsystem-boilerplate.git"
  },
  "bugs": {
    "url": "https://github.com/stencil-community/designsystem-boilerplate/issues"
  },
  "scripts": {
    "build": "ng-packagr -p ng-package.json"
  },
  "files": [
    "dist"
  ],
  "peerDependencies": {
    "@angular/common": ">=14.3.0",
    "@angular/core": ">=14.3.0",
    "rxjs": ">=7.5.0"
  },
  "keywords": [],
  "devDependencies": {
    "ng-packagr": "^16.2.3",
    "typescript": "~5.5.0",
    "tslib": "^2.3.0"
  },
  "dependencies": {
    "@placid/core": "workspace:^"
  },
  "publishConfig": {
    "access": "public"
  }
}
```

## Add ng-packagr [configuration](https://github.com/ng-packagr/ng-packagr/blob/main/docs/configuration-locations.md)

Create a file an `ng-package.json` file in the `packages/angular` directory with the following content:

```json
{
    "$schema": "./node_modules/ng-packagr/ng-package.schema.json",
    "dest": "./dist",
    "allowedNonPeerDependencies": [
      "@placid/core"
    ],
    "lib": {
      "entryFile": "src/public_api.ts"
    }
}
```

## Install the Framework Wrapper

Switch back to the Stencil project and add the Angular Framework Wrapper. As always, adjust the following commands for your own directory structure.

```bash
cd ../core
pnpm add -D @stencil/angular-output-target
```

The Angular Framework Wrapper is configured in a similar manner to the other output targets. We will use a set of options that allow us to export the output of the `dist-custom-elements` build. That is, we are publishing the ES6 modules. See the [framework wrapper documentation](https://github.com/ionic-team/stencil-ds-output-targets/blob/main/packages/angular-output-target/README.md) for a full set of options.

```typescript
import { Config } from '@stencil/core';
import { angularOutputTarget } from '@stencil/angular-output-target';
...

export const config: Config = {
  ...
  outputTargets: [
    angularOutputTarget({
      componentCorePackage: '@placid/core',
      outputType: 'standalone',
      directivesProxyFile: '../angular/src/lib/components.ts'
    }),
    ...
  ]
}
```

Run a build from the `packages/core` directory. It should succeed, and the files in `../angular/src/lib/stencil-generated` should be successfully created. It is now time to clean up the Angular library.

Run `pnpm build` from the `packages/core` directory to generate an Angular library.

## Clean up the Angular Library

Switching back to the Angular library (`cd ../angular`), we need to perform the following cleanup:

Create the `src/public_api.ts` file to define the entry point for your library. This file should export all the components and modules you want to expose to the consumers of your library. For example:

```bash
echo "export * from './lib/components';" > src/public_api.ts
```

## Create Angular Consumer Application

Let's create an Angular application to test the library. We'll create an Ionic Starer App. From the root of the project, run the following commands:

```bash
cd ./apps
```

## Notes

1. In this project, we've defined an `apps` directory in the root of the project. This is where we will create our Angular application to test the library. You can adjust this to fit your own project structure.
2. See the [consumer usage](https://stenciljs.com/docs/angular#consumer-usage) section of the documentation for tips on how to efficiently consume the package in an Angular application.
3. This document was written using the naming conventions within this project. You can (and should) adjust for your own project.
